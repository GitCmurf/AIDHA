# Vite 8.1.6 Toolchain Maintenance

## Version History

| Version | Date | Author | Change Summary | Reviewers | Status | Reference |
| ------- | ---- | ------ | -------------- | --------- | ------ | --------- |
| 0.1 | 2026-11-03 | Codex | Qualify the compatible Vite update and its required Rolldown closure with bounded consumer and CLI checks | — | Draft | Owner autonomous progress request |

## Problem and scope

Dependabot alert 45 identifies locked Vite 8.0.12 as affected by
[GHSA-587h-7wmj-h5pm][advisory]. The advisory names Vite 8.1.6 as the first fixed
release for this version line. Update the existing development test toolchain to
that version and its required dependency closure, retaining the source-map-js 1.2.2
patch qualified by [AIDHA-TESTING-099](testing-099-source-map-maintenance.md).

The installed Vite 8.1.6 bundle includes launch-editor and launch-editor-middleware
2.14.2. Static inspection finds the upstream [path-resolution fix][upstream-fix]:
the editor parser removes the position suffix and resolves the remaining path
before the existence check. The bundle also rejects Windows shell arguments
containing percent characters or line breaks and rejects UNC editor paths.
These observations establish which code is installed; no editor command or
exploit payload is executed.

## Dependency contract and exact closure

Installed and registry Vitest 4.1.11 independently declare
`dependencies.vite: ^6.0.0 || ^7.0.0 || ^8.0.0`. Vitest and its mocker also declare
that same Vite peer range. The regular dependency contract and the peer contracts
therefore admit 8.1.6. Their upstream package metadata remains unchanged.
Vite requires Rolldown `~1.1.5`; the selected version is 1.1.5.

| Package group | Before | After |
| --- | --- | --- |
| Vite | 8.0.12 | 8.1.6 |
| Rolldown | 1.0.0 | 1.1.5 |
| Fifteen Rolldown binding packages listed below | 1.0.0 | 1.1.5 |
| `@oxc-project/types` | 0.129.0 | 0.139.0 |
| `@emnapi/core`, `@emnapi/runtime` | 1.10.0 | 1.11.1 |
| `@emnapi/wasi-threads` | 1.2.1 | 1.2.2 |

The binding package suffixes below share the `@rolldown/binding-` prefix:

```text
android-arm64
darwin-arm64
darwin-x64
freebsd-x64
linux-arm-gnueabihf
linux-arm64-gnu
linux-arm64-musl
linux-ppc64-gnu
linux-s390x-gnu
linux-x64-gnu
linux-x64-musl
openharmony-arm64
wasm32-wasi
win32-arm64-msvc
win32-x64-msvc
```

The published WASM binding requires exact EMNAPI core/runtime 1.11.1, making those
updates part of the Rolldown closure. Its existing wasm-runtime 1.2.4 is retained;
only that package's EMNAPI peer context changes. PostCSS 8.5.28, source-map-js 1.2.2,
Nano ID 3.3.19, wasm-util 0.10.3 and tslib 2.8.1 remain selected.

Canonical comparison against main `aa80e6cd` confirms 156 unrelated package records
are equal. The 156 unrelated snapshots and all importer requirements are equal
after normalising only the named Vite and EMNAPI peer-context references above.
Original root manifest bytes, override metadata and complete Vitest/mocker package
records are preserved. The final graph is generated by the pinned package manager.

## Reproducible resolution workflow

Use an isolated clean worktree and preserve the original root manifest bytes.
Temporarily declare `devDependencies.vite: 8.1.6` in root `package.json`, then run:

```bash
pnpm install --lockfile-only --ignore-scripts
pnpm remove --workspace-root --lockfile-only vite
```

Restore the saved original root manifest bytes, verify the existing override
metadata is unchanged, and inspect the generated lockfile. This temporary root
dependency selects the new artifact through the real workspace's peer resolver;
pnpm removes it while retaining the compatible transitive selection.

The earlier transitive-update and temporary-override attempts retained Vite 8.0.12.
Their successful command exits were rejected as qualification. The final candidate
is accepted only after the installed artifact is 8.1.6 and frozen strict-peer
installation succeeds. No direct dependency or override is retained.

## Acceptance and bounded verification

The official pre-change advisory provides the independent affected baseline.
Use existing public-boundary checks for compatibility:

- [Source-map consumer][consumer]: transform mapped CSS through the actual
  installed Vite/PostCSS/source-map dependency chain, preserving source positions
  and original source text.
- [NLP utilities][runner]: exercise TypeScript module loading and a transformed
  asynchronous mock through the installed Vitest and Vite runner.
- [Package-script guards][scripts]: preserve the normal serial and exhaustive
  package dispatch, including the source-map regression.
- [Offline public CLI][cli]: ingest mock material through a real child process
  with an in-memory database and verify it is absent on reopen.
- [Knowledge search][knowledge]: exercise saved prose, updates, deletion,
  older-index recovery and complete-index reuse through the SQLite API.

Run the selected CLI prerequisites and test files serially, with one Vitest worker
and existing test budgets. Commands from the repository root:

```bash
pnpm install --frozen-lockfile --strict-peer-dependencies
pnpm --filter @aidha/ingestion-youtube... --fail-if-no-match --workspace-concurrency=1 -r build
pnpm test:source-map
pnpm --filter @aidha/ingestion-youtube exec vitest run tests/nlp-utils.test.ts tests/package-scripts.test.ts tests/cli-memory-database.test.ts --maxWorkers=1 --no-file-parallelism
pnpm --filter @aidha/graph-backend exec vitest run tests/sqlite-knowledge-fts.test.ts --maxWorkers=1 --no-file-parallelism
node scripts/meminit-check.mjs docs/55-testing/testing-100-vite-toolchain-maintenance.md
pnpm docs:build
```

Frozen strict-peer installation and the five prerequisite builds pass on Node
24.22.2 with pnpm 9.12.0. The source-map consumer passes one case, NLP/mock loading
passes 74 cases, and the package-script guard passes four cases. The Knowledge
lifecycle case passes, while its two file/reopen cases exceed their existing
five-second limits. The offline CLI exceeds its unchanged 20-second subprocess
limit in both the combined run and one isolated retry. These timed-out checks
remain unqualified; no further local retries or timeout changes are made.

The full local workspace suite is not repeated. Full hosted default CI and actual
reporting review bots must pass before merge, including the timed-out boundaries.

Local verification exercises native Linux x64 bindings. Other native platforms
and the optional WASM fallback are not executed here. The retained wasm-runtime's
engine range already excludes Node 22.12; this slice establishes no additional
floor-runtime or cross-platform support claim. Preserve existing assertions,
timeouts and skips, and keep the full hosted suite as the final integration gate.
